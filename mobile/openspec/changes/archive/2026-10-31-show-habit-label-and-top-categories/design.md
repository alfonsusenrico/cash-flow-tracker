# Design

## Context
The worktree starts at mobile main 2cd2572 (2.3.2, code 24, Room v9). Both server fields were read at cash-flow-tracker origin/main 26e04af with `git show`:

- `backend/app/services/notification_processing.py` (`compact_result`): for a `recorded` expense or income that is not a move, a companion that supports purpose questions (1.8.0 and later) gets `"habit": {"label": habit_label(category_name), "basis": basis_text(agreeing, support)}` when `transactions.classified_by = 'habit'` and the event's interpretation holds the habit basis.
- `backend/app/services/habits.py`: `habit_label` returns "Dicatat dari kebiasaan: <category>", or "Dicatat dari kebiasaan" without a category; `basis_text` returns "<agreeing> dari <support> jawaban sebelumnya".
- `backend/app/routers/dashboard.py` (`get_cash_flow_summary`) has no `top_categories` at 26e04af. The field is the coordinator's fixed additive contract: `[{category_id, name, kakeibo_type (need|want|culture|unexpected|saving|null), outflow}]`, at most three, sorted by outflow descending, the same period and rules as `outflow`, an empty list when nothing was spent, absent on older servers. `git ls-remote origin refs/heads/chore/small-follow-ups` returned nothing on 2026-10-31, so the phone is tested against MockWebServer only.

## Goals / Non-Goals
Goals: show the tracker's habit decision on the row it recorded; bring back "Kategori teratas" from the tracker's own figures. Non-goals: any backend change, phone-side category or habit computation, captures, Room.

## Decisions
1. **The habit lives in the stored result JSON.** `IngestResultItem` gains an optional `habit` (`RecordedHabit`). `NotificationResults.consume` already stores the whole recorded result as `result_json`, so the habit persists without a Room change, and every later result replaces it, which removes the tag when the tracker stops reporting it. Rejected: a new column and migration to v10, which would duplicate data the row already holds.
2. **Only a complete habit is shown.** `RecordedHabit.shown()` needs a non-blank label and basis of at most 200 characters each; otherwise the habit is ignored and the result is still recorded. It is shown only for a recorded `expense` or `income`, the only results the tracker attaches it to. Rejected: rejecting the whole result for a malformed optional field.
3. **Rincian keeps the tracker's wording.** The tracker's label already reads "Dicatat dari kebiasaan: Makan & Minum", so Rincian shows "<label> · <basis>". The approved copy "Dicatat dari kebiasaan: <label> · <basis>" would repeat the prefix with the real label; a label without the prefix (a bare category name) gets it added. Rejected: parsing the category out of the label.
4. **The Aktivitas tag is quiet and spoken.** "Dari kebiasaan" is a muted pill with a history icon beside the status badge (both in the row's `FlowRow`, so it wraps at large text). The row's TalkBack description adds "Dari kebiasaan" after the status. The muted pair is already in `ContrastTest`. Rejected: a new status ("Tercatat otomatis"), which would change filters and counts.
5. **Top categories ride on the summary.** `LedgerCashFlowSummary` gains an optional `topCategories`. The summary is cached as JSON per pairing, so the categories are stored, restored, marked stale and dropped on re-pairing exactly with the totals, through the existing code. Gson leaves an absent field null and keeps an empty list empty, so "absent" and "nothing spent" stay distinct after a restart.
6. **A broken list hides the tile, not the summary.** `shownTopCategories()` returns null for more than three entries, a null entry, a blank name, a missing or negative outflow, an unknown pillar, or entries not sorted descending. The totals still show. Rejected: making the summary incomplete, which would hide the tracker's totals for a problem in an optional field; re-sorting on the phone, which would silently repair a contract break.
7. **The tile.** "Kategori teratas" sits below "Arus kas tracker", is static (no drill-in: the phone has no list of the tracker's categories), and shows each category's name and amount, its pillar in the web's words (Kebutuhan, Keinginan, Budaya, Tak Terduga, Tabungan; nothing for null), and a bar relative to the first (largest) entry, then the summary's "Periode" and freshness lines and any refresh error. Both tiles use the same period and freshness helpers. Each category is one TalkBack node, "Belanja Rumah, Rp410.000, Kebutuhan"; the bars are not spoken. No summary at all (loading, unpaired, refused) shows no tile.
8. **Bar colours.** New tokens `bar` and `barHighlight` (the largest bar): light #0F1012 and #D9531C, dark #8A8E96 and #FF7A45. Each reaches 3:1 against the tile and against its track in both themes (`ContrastTest`), although every bar's value is also written as text.
9. **Spec deltas.** `companion-interface`: "Accessible screens" gains the scenario "Amounts and day headers at large text", with every existing scenario kept; "Top categories come from the tracker or are not shown" is modified with both scenario names kept; "Beranda money comes only from the tracker's summary" now names the categories tile as the second place for tracker money; "Home figures come from this phone's rows" keeps every scenario, and "Nothing recorded in three days" now says no category computed on the phone, because the tracker's tile can be shown; "Rows recorded from a habit say so" is added.

10. **Amounts never break at large text (coordinator follow-up, 2026-10-31).** Beranda's `Figure` (a label and its value, such as "Dikurangi penggantian Rp50.000") was a `Row`: the label was measured first, so the value got the remaining width and broke mid-number ("Rp / 50 / .0 / 00" at font 2.0 on 360 dp). It is now a `FlowRow` whose value is one unbreakable line (`softWrap = false`), so the value moves below the label when both do not fit, and the label wraps between words on its own. The TalkBack text (`"$label $value"`) and tabular figures are unchanged. "Menunggu n notifikasi · m catatan" is a count phrase, not an amount, and still wraps between words. Rejected: shrinking the amount's font, which would break the scaled size the owner chose; ellipsizing, which hides the figure.
11. **Day headers wrap between words (same follow-up).** Aktivitas' day header was a `Row` with the date weighted and "Keluar Rp…" measured first, which squeezed the date into a narrow column (5 lines on 360 dp, 13 on 320 dp, breaking "KAMIS," from "29"). It is now a `FlowRow` with `SpaceBetween`: on one line when both fit (font 1.0 is unchanged), otherwise "Keluar Rp…" moves below the date. The date uses no-break spaces, so "Kamis, 29 Okt" stays together and a long label breaks after "Hari ini ·". "Keluar Rp…" is one unbreakable line. The heading semantics and spoken text are unchanged. Rejected: dropping the day total at large text, which removes meaning.
12. **Testing real line breaks.** `LargeTextAmountsUiTest` runs with Robolectric native graphics (as `BottomBarUiTest` does), so the bundled Archivo font is measured as on a phone, at font scale 2.0 on 360 and 320 dp in both themes. It reads every text's `TextLayoutResult` from the unmerged semantics tree, which still holds the texts under a tile's single TalkBack node, and asserts that each "Rp…" amount starts and ends on one line and fits its width, and that day headers take at most two lines, break only at spaces and keep the date on one line. Against the previous layout all 8 cases fail ("Rp50.000 … expected:<0> but was:<3>", "\"HARI INI · KAMIS, 29 OKT\" takes 5 lines"). Amounts drawn by `MoneyText` clear their own text semantics and are not reached by this check; they sit in a non-weighted slot and get their full width first.

## Data, API and failure behaviour
- No new request. `GET /api/ingest/notifications/{id}/result` and `GET /api/dashboard/cash-flow-summary?period=today` are read as before; both new fields are optional.
- Older trackers: no habit tag, no categories tile; everything else unchanged.
- Nothing new is logged. The habit and categories are personal data and stay in Room and the app preferences, which are excluded from backup as before.

## Migration and rollback
No schema or preference change. Installing 2.3.3 over 2.3.2 keeps every row and setting. Rows recorded before 2.3.3 have no stored habit, because older builds dropped the field; they show the tag only if the tracker's result is read again. A rollback to 2.3.2 (same Room 9, installed as a downgrade) hides both features; its Gson model ignores the extra fields in the stored JSON.

## Risks / Trade-offs
- The tag reflects the result the phone last read. If the owner reclassifies the transaction on the web and the phone never re-reads that result, the tag stays. This is the same staleness every recorded field on the phone has.
- At font scale 2.0 a long category name wraps beside its amount; the amount stays whole.
- The two tiles repeat the same period and freshness lines; this keeps each tile self-explaining for TalkBack.

## Open decisions for owner
1. **Rincian wording.** Shown as the tracker's label plus basis, without repeating "Dicatat dari kebiasaan" (decision 3).
2. **Malformed categories.** Hidden rather than repaired (decision 6). The alternative is to sort on the phone and drop invalid entries.
3. **Pillar for categories without one.** Nothing is shown. The web treats a missing pillar as "need" in forms; the phone does not guess.
4. **Pre-existing at font scale 2.0.** The summary tile's broken amount and Aktivitas' squeezed day header were found in the first JVM render and fixed in the same change at the owner's request (decisions 10 and 11).
