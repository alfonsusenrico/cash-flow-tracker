# Design

## Context
The worktree starts at mobile main 4a11eb0 (2.3.0, code 22, Room v8). Beranda shows the tracker's "Arus kas tracker" tile (merged in 2.2.0 without an OpenSpec change, so no requirement describes it yet) next to "Keluar tercatat hari ini", a sum of this phone's recorded notifications and captures with Masuk, Pindah, Menunggu and a three-day money strip, and "Kategori teratas · 3 hari", also summed on the phone. The backend contract was read at cash-flow-tracker origin/main 02f4468 with `git show`: `backend/app/routers/dashboard.py`, `backend/app/services/auth.py`, `backend/app/services/report_windows.py`, `backend/app/routers/pulse.py`, `backend/app/routers/categories.py` and `backend/app/main.py`.

## Goals / Non-Goals
Goals: Beranda's only money is the tracker's summary; this phone's activity stays visible as truthful counts; top categories only from the server. Non-goals: a backend endpoint, Aktivitas and Rincian, Room, sync, capture and pairing.

## Decisions
1. **Money on Beranda only from the tracker.** "Keluar tercatat hari ini" with Masuk and Pindah, and the three-day strip, are removed rather than relabelled. A local sum cannot match the web: it misses what was recorded on the web or another device, and ignores the server's reimbursement offsets and reportable-category rules. Rejected: keeping the local sum under a clearer label, which the owner already found confusing next to the server figure.
2. **An activity tile of counts.** "Aktivitas ponsel hari ini" shows the notifications captured today as the large figure, then "Menunggu n notifikasi · m catatan", then "Dari notifikasi dan catatan di ponsel ini", and opens Aktivitas with Semua. "Captured today" counts rows posted today in the lists the companion shows (sent, kept on the phone and ignored; dismissed rows, drops and hidden duplicates are not listed, so they are not counted), distinct by id. "Menunggu" keeps its previous meaning: sent rows, or rows about to be sent, not yet settled as recorded, ignored or dismissed. Typed captures waiting are those not yet recorded (queued, sending, refused, asking). Rejected: counting recorded typed captures in "captured", because "notifikasi tertangkap" names notifications; and per-app counts, which Aktivitas already has.
3. **Unknown is never 0.** `CompanionLists` gains `loaded`, set once Room answers, and `CaptureViewModel.visible` starts as null instead of an empty list. Until then each count shows "—" and TalkBack reads "belum dimuat". Aktivitas reads the captures with `orEmpty()`, as before. Rejected: a second Room subscription for a loaded flag. After the coordinator's review the same rule covers every Beranda count: "Perlu cek" and "Di ponsel" show "—" ("belum dimuat") until both notification rows and typed captures are read, and "Pertanyaan" says "Belum dimuat" instead of "0 · Semua terjawab" until the rows are read.
4. **No top categories.** The server has no per-category amounts for the summary's period. `/api/dashboard/cash-flow-summary` returns totals only (`period` today or month). `/api/dashboard/overview` and `/api/dashboard/analytics` accept Bearer keys through `get_current_user` and return per-category `spent`, but only for `timeframe` cycle, 30d, 90d or month, and they also compute balances, net worth and narratives the phone does not need. `/api/pulse` lists today's transactions and the most used categories by count, not amounts. Showing a different period beside today's summary, or summing today's transactions on the phone, would recreate the mismatch this change removes. So the tile is removed and a server endpoint is a follow-up. Rejected: `/api/dashboard/analytics?timeframe=month` labelled as this month, which the owner did not approve and which puts two periods on one screen.
5. **The server tile stays as it is.** No change to its request, cache per pairing, refresh, stale and offline states, or copy. A new requirement now describes it, because none did.
6. **Footer.** "Uang di Beranda hanya dari arus kas tracker. Hitungan lain di sini berasal dari notifikasi dan catatan di ponsel ini." It keeps the phrase the device screenshot walk scrolls to.
7. **Remove what only the removed tiles used.** `HomeFigures` keeps its name and file but holds counts only; `DayOut`, `CategoryTotal`, the `bar` and `barHighlight` colour tokens, `Formatting.thousands` and `Formatting.barDay` are removed, and the contrast test drops the two bar pairs and its "supplementary" kind. `MoneyFact` stays because Aktivitas uses it for its per-day money out.
8. **The Pertanyaan tile keeps the next question's amount.** It names one question ("Apa ini? Rp187.500"), like a row in Aktivitas, and is not a total. The UI test allows exactly that amount besides the tracker's.
9. **Bottom-bar labels fit at large text.** At font scale 2.0 the labels were cut ("Berand", "Aktivit"), because each tab is about 57–67 dp wide. Each tab label is now drawn at the owner's scaled size and reduced in 0.25 sp steps only until the whole word fits the tab, never below its size at font scale 1.0; it stays on one line. At 2.0 on a 360 dp phone this gives about 16.5 dp for Beranda and Aktivitas and the full 23 dp for Tanya and Atur. The tab's TalkBack name is unchanged: the tab now merges its label instead of clearing it, with the description kept as the spoken name and the question badge hidden from TalkBack because the name already says the count. Catat keeps its fixed scaled size, which fits, and merges its label the same way. Rejected: wrapping to two lines, which breaks single words mid-word in a 57 dp tab; a fixed smaller label, which would not scale at all.
10. **Spec deltas.** `companion-interface`: "Home figures come from this phone's rows" and "Home tiles open their list" are modified with every scenario name kept and reworded where the meaning changed; "Accessible screens" gains the scenario "Bottom bar at large text"; two requirements are added for the tracker summary and for top categories. `mobile-text-capture`: "Captured money never enters the tracker's summary" no longer names "Keluar tercatat hari ini".

## Data, API and failure behaviour
- No new request. `GET /api/dashboard/cash-flow-summary?period=today` with the Bearer key is unchanged, as are its stored copy and its error messages.
- The counts come from Room flows already collected for Aktivitas; nothing is logged.
- Before Room answers, counts are "—"; an empty day after Room answers is 0.

## Migration and rollback
No schema, preference or API change. Installing 2.3.1 over 2.3.0 keeps every row and setting; reinstalling 2.3.0 restores the old tiles.

## Risks / Trade-offs
- The owner loses the at-a-glance three-day strip and categories until the tracker offers them for today.
- The JVM UI tests cover captures waiting; the device seed has no typed captures, so the device screenshots show the tile without "· n catatan".

## Open decisions for owner
1. **Server top categories.** Conservative choice: no tile. Follow-up: extend `/api/dashboard/cash-flow-summary` with the `category_breakdown` rows for the same window (name, spent after reimbursements), then show the top three with the summary's period and freshness.
2. **Aktivitas per-day money out.** Kept, because the approval covers Beranda and Aktivitas is per-item. It is still a local sum per day; it could move to counts later if it causes the same confusion.
3. **Bottom-bar label size at large text.** The label shrinks only to fit and never below its 1.0 size. If the owner prefers labels at the full scaled size, the alternative is icons only with labels in TalkBack at font scale 1.5 and above.
